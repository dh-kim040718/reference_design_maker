# Phase 5 — 키 없는 재생성 준비·영역 선택 실험

**최신 실제 평가:** [Phase 4·5 실제 연동 평가](./phase-45-live-evaluation.md). 실제 편집 어댑터를 추가해 승인된 재생성 1회·지시 편집 1회·무지시 변형 1회를 수행했다. 전송/결과/이력/삭제는 검증했지만 보호 영역과 카드 내용 보존에 실패해 편집은 비활성화 유지다. 아래 미연결·미실행 설명은 당시 선행 구현 기록이다.

실제 재생성·영역 편집의 미완료 항목은 [보류 작업 체크리스트 API-10~16](./deferred-api-work.md)에서 추적한다. 아래 구현/mock 검증 완료와 실제 제공자 검증 완료를 구분한다.

2026-11-02: 사용자가 API 키가 필요한 작업을 제외하고 후속 작업 진행을 요청했다. Phase 4 실제 성공·품질·청구 게이트는 미완료로 유지하고 독립적인 로컬 작업만 선행했다. 실제 이미지 생성·편집 API는 호출하지 않았다.

## 구현된 흐름

- 완료된 결과에서 **전체 재생성 준비**를 누르면 같은 레퍼런스의 새 생성 화면으로 이동한다. 이전 추가 요청을 가져오고 이전 메모와 현재 메모를 구분해 보여준다. 원본 이미지는 저장하지 않으므로 다시 선택해야 한다.
- 준비 화면 이동·과거 요청 조회만으로 생성하지 않는다. 새 화면은 새로운 요청 ID를 사용한다. 명시적인 생성 버튼과 기존 서버 활성화·권한·횟수 제한이 그대로 적용된다. 이전 결과를 덮어쓰지 않는다.
- 업로드/저장된 미리보기 선택 후 **영역 편집 준비 · 로컬 실험**을 펼치면 사각형 영역을 선택할 수 있다. 성공 결과에도 동일한 도구를 제공한다.
- 마우스·터치 드래그와 키보드로 조작 가능한 좌표/크기 입력을 제공한다. 이미지 바깥으로 벗어난 선택은 경계에 제한하며 초기화할 수 있다.
- 마스크 다운로드는 원본 이미지의 가로·세로 크기를 유지하는 PNG다. 선택 영역은 투명, 나머지는 불투명 흰색이다. 반대 방향 드래그, 축소된 화면, 소수점 계산, 빈 영역을 처리한다.
- 이미지·영역·마스크는 브라우저 메모리에서만 처리한다. 선택과 다운로드는 서버 요청이나 유료 호출을 만들지 않는다. 원본 교체·화면 이탈 시 선택을 유지하지 않는다.

## 검증 및 한계

- 프런트엔드 41개 테스트, 타입 검사 포함 production build 및 lint 통과.
- 새 테스트는 좌표/픽셀 경계·반대 드래그, 원본 크기/투명 영역을 만드는 canvas 동작, 재생성 준비 중 POST 부재 및 이전 추가 요청 복원을 검증한다.
- 실제 브라우저 smoke에 마스크 PNG 디코딩 후 원본 크기·선택 영역 alpha=0·외부 alpha=255 확인을 추가했다. 실행 결과는 출시 준비 기록에 남긴다.
- 사각형 한 영역만 지원한다. 자유형 브러시·다중 영역·실제 영역 편집·결과 비교는 구현하지 않았다. 아래 후속 구현에서 서버 입력 계약과 mock 전송 검증을 추가했으나 실제 AI 편집 성공으로 취급하지 않는다.
- 이전 생성 결과를 자동으로 다음 입력에 넣지 않는다. 현재 저장된 디자인 메모와 이전 추가 요청을 사용자가 확인한 뒤 재생성하도록 준비한다.

## API가 필요한 보류 항목

실제 전체 재생성과 영역 편집 제공자 연결, 제공자 마스크 계약 검증, 주변 영역 보존·요청 영역 일치·시각 품질·실패율·시간·비용 측정은 별도 승인과 품질 검증 후 진행한다. 영역 편집 출시 기능은 계속 비활성 상태이며 Phase 5 완료 게이트는 통과하지 않았다.

## 후속 구현 — 키 없는 편집 요청 계약

- `POST /api/v1/references/{id}/edits` 추가. 입력은 `request_id`, `source_image`, `mask_image`, 선택 `direction`(기존 디자인 방향, 최대 5,000자), 선택 `instruction`(새 편집 지시, 최대 2,000자), `rights_confirmed`다. 디자인 메모 스냅샷은 서버가 현재 레퍼런스에서 가져온다.
- 서버는 소유권·보관 상태·권한 확인, 이미지 디코딩, 같은 크기의 PNG 마스크, 투명 픽셀과 불투명 보호 픽셀 존재를 검증한다. 투명 영역 없는 마스크·전체 투명 마스크·PNG 아닌 마스크는 차단한다.
- 생성과 편집은 `(owner_id, request_id)` 중복 방지, 전체 UTC 일 3회 한도, 사용자별 진행 작업 1개 제한을 공유한다. 같은 요청의 이미지·마스크·기존 방향·지시·작업 종류가 변경되면 충돌로 거절한다. 실패·결과 불명도 횟수를 반환하지 않는다.
- 작업에 `operation=edit`와 기존 `direction`을 따로 저장한다. 원본·마스크 본문은 작업 메모리에서만 처리하며 DB에 저장하지 않는다. 입력 해시로 요청 동일성을 확인한다. Alembic head는 `0006_editing_contract`다.
- 결과 상태/조회·이력·다운로드·삭제는 기존 Generation API를 재사용한다. 목록에는 이미지 본문이 없고 상세는 소유자만 조회한다. 이력은 영역 편집과 전체 생성을 구분한다. 기존 방향과 선택 지시는 프롬프트에서 분리하며 지시가 비면 선택 영역 내부 변형으로 정의한다.
- 선택한 마스크에서 **선택 영역 편집 준비**를 누르면 기존 방향과 선택 지시를 따로 입력할 수 있다. 생성 정책의 `editing_enabled`가 false면 실행 버튼은 차단된다. 준비는 이미지·마스크를 서버에 보내지 않는다. 연결 실패 후 같은 입력으로 다시 요청하면 같은 요청 ID를 유지하며 입력을 잠근다.
- 편집 제공자는 기본 `None`이며 실제 API 어댑터는 없다. `image_editing_enabled` 기본값도 false다. 환경 설정만 바꾸어 실제 호출할 수 없고, 테스트에서만 오프라인 제공자 의존성을 주입한다. 실제 호출 가능한 mock 모드를 운영 사용자에게 제공하지 않는다.
- 이미지/영역이 바뀌면 준비한 폼을 초기화한다. 마스크 선택·PNG 다운로드는 계속 로컬 작업이다.

실제 품질 평가에 사용할 [비교 계획·기록 양식·제안 기준](./phase-5-evaluation.md)을 준비했다. 비용·지연 기준과 품질 판정은 실측 전에 별도로 합의해야 한다.

### 후속 검증 결과 — 2026-11-02

- 백엔드 비통합 65개·PostgreSQL 통합 29개 통과. SQLite 마이그레이션 왕복과 메타데이터 일치 포함. 앱 DB도 `0006_editing_contract` 적용 완료.
- 프런트엔드 44개·빌드·lint, 백엔드 lint, 공개 산출물 비밀 패턴 검사 통과.
- Chrome·Edge에서 마스크 원본 크기·alpha, 편집 준비 폼 표시와 실행 차단, 390px 가로 넘침 없음, 기존 저장·메모 수정·재조회·로그아웃 확인.
- mock은 별도 API 키 없이 성공/실패/불명·동일 요청 재제출·변경 충돌·계정 격리·삭제·진행 중 차단·오래된 상태 전환·생성/편집 공통 한도를 검증했다. 브라우저는 비활성화 상태만 검증했으며 실제 편집 성공 화면은 단위/mock 검증이다.
- 유료 호출·실제 결과 품질·청구 확인은 수행하지 않았다. Starlette/httpx 호환성 경고 1개는 남아 있다.
