# AI 시안 대기 화면 UX 조사 및 제안

조사일: 2026-11-03. 사용자 요청에 따른 조사 문서이며 화면 구현은 변경하지 않았다.

## 결론

텍스트 기록 중심 화면을 ‘생성 작업 공간’으로 바꾼다. 큰 결과 캔버스, 실제 작업 상태,
요청 후 경과 시간, 선택한 참고 자료 요약을 우선 배치하고 상세 입력은 접는다.
시각적인 움직임은 작업이 살아 있다는 피드백으로 사용하며 실제 진행률로 오인시키지 않는다.
화면 체류 자체보다 작업 포기 감소와 완료 결과로의 복귀를 목표로 한다.

## 현재 화면 진단

- 결과가 없는데 ‘생성 결과’를 제목으로 사용해 현재 상태와 제목이 어긋난다.
- 펼친 사용 현황 상자가 상단 공간을 차지하고 생성 진행보다 먼저 보인다.
- 프로젝트 입력·레퍼런스 메모·사용한 메모가 반복되며 결과 영역은 없다.
- 생성 중인지 상태 조회가 끊긴 것인지 구별하기 어렵다.
- 현재 `GenerationPage`는 상태 조회 오류 시 다음 폴링을 예약하지 않아 화면이 멈춘 것처럼 보일 수 있다.
- 분류/선택 생성에도 프로젝트 ‘전체’를 검토했다는 문구가 표시될 수 있어 범위 표현 수정이 필요하다.

## 추천 화면

상단 한 줄: 뒤로가기 / 프로젝트명 / AI 시안 / 생성 중 배지.

중앙은 큰 캔버스, 우측은 280~320px 요약 패널로 구성한다. 모바일은 캔버스·상태가 먼저 나온다.

캔버스에는 얇은 격자와 낮은 대비의 카드 윤곽이 짧게 교차하는 움직임을 사용한다.
이는 생성 대기 연출이며 실제 중간 결과가 아니다. 제공받지 않은 시안이나 분석 결과를 만들지 않는다.
참고 썸네일을 쓰는 경우 ‘참고 이미지’라는 표시로 생성 결과와 구분한다.

중앙 문구 예:

> lgax의 새 시안을 만들고 있어요
>
> 선택한 레퍼런스 4개와 메모를 참고해 생성 중입니다.
>
> 입력 확인 완료 → 생성 중 → 완료
>
> 요청 후 00:38 경과

우측 요약:

- 프로젝트/선택 분류와 참고 자료 개수
- 요구사항 원문 두 줄 + 펼치기
- 선택한 참고 자료의 작은 이미지 목록
- ‘입력 내용 자세히’ 아코디언
- ‘레퍼런스 둘러보기’ 링크

전체 프롬프트, 반복 메모, 토큰/예산 설명은 기본 접힘 상태로 둔다.

## 실제 상태와 표시 기준

현재 서버는 `queued`, `processing`, `succeeded`, `failed`, `unknown` 상태와 요청 생성 시각을 제공한다.
생성 중간 이미지, AI 내부 단계별 진행률, 신뢰할 수 있는 남은 시간은 제공하지 않는다.

| 실제 신호 | 화면 표현 |
| --- | --- |
| 생성 요청 접수 및 입력 검증 완료 | 입력 확인 완료 |
| queued | 생성 대기 중 |
| processing | 시안 생성 중 + 퍼센트 없는 활동 표시 |
| succeeded | 동일한 캔버스 안에 결과 표시, 다운로드 CTA 등장 |
| 상태 GET 오류 | 마지막으로 확인된 상태 유지 + ‘진행 상태 연결 중’과 조회 재시도 |
| failed | 실패 원인과 복구 행동 표시 |
| unknown | 결과 확인 필요. 조회만 제공하고 유료 요청을 자동 재전송하지 않음 |

경과 시간은 요청 생성 시각 기준이며 남은 시간이나 완료율로 해석하지 않는다.
평균 시간은 충분한 동일 모델·설정의 실제 표본을 확보한 뒤 범위와 함께 검토한다.
코드의 HTTP 타임아웃을 예상 생성 시간으로 안내하지 않는다.

## 움직임과 체류 경험

- 작은 참고 카드/캔버스 표면을 낮은 대비로 교차 노출한다. 큰 회전·튀는 확대·빠른 문구 교체는 제외한다.
- 준비된 입력 개수와 현재 상태를 고정 표시한다. 매초 바뀌는 안내는 경과 시간뿐이다.
- 완료 결과는 같은 자리에서 180~240ms 정도로 등장하도록 제안한다. 보기 위한 불필요한 지연은 추가하지 않는다.
- `prefers-reduced-motion`에서는 연출을 끄고 텍스트 상태는 유지한다.
- 서버가 실제 결과를 보내기 전 가짜 시안, ‘색상 분석 80%’ 같은 내부 단계, 99%에 멈춘 진행률을 표시하지 않는다.

## 화면 이동과 복귀

긴 대기 동안 사용자가 레퍼런스를 탐색할 수 있게 한다. 앱 상단에 ‘시안 생성 중 1’ 진입점을 두고,
완료되면 ‘시안 완성 · 결과 보기’로 바꾼다. 이것은 신규 기능으로 구현이 필요하다.
브라우저 푸시 권한을 처음부터 요청하지 않는다.

현재 작업은 서버 프로세스가 살아 있는 동안 화면 이동과 독립적으로 실행되지만,
원본 비보관 정책 때문에 서버 재시작 후 자동 재개는 지원하지 않는다. 이를 무조건적인 영구 백그라운드 보장으로 표현하지 않는다.

## 구현 순서

1. 대기/완료/실패 화면 분리, 중복 텍스트 접기, 캔버스와 상태 중심으로 재배치.
2. 상태 GET 폴링의 연결 복구, 경과 시간과 지연/오류 상태를 실제 신호에 연결.
3. 앱 전역 진행 작업 진입점과 완료 후 복귀 동선.
4. 참고 이미지 보드와 절제된 전환 연출. 원본 영구 저장은 추가하지 않음.

서버 입력 스냅샷에는 원본 이미지가 없다. 썸네일은 소유권·버전 확인이 가능한 기존 미리보기나
현재 세션에서만 제공하고, 없으면 일반 그래픽을 사용한다. 서버 저장 정책을 바꿔 연출을 구현하지 않는다.

## 검증 기준

- 처음 5초 안에 사용자가 현재 상태와 선택 자료 범위를 설명할 수 있는지 관찰한다.
- 이미지 준비/대기/완료/지연/연결 오류/결과 불명 각각의 화면을 mock으로 검증한다.
- 재연결 과정에서 유료 POST가 반복되지 않는지 확인한다.
- 결과 확인율, 완료 후 결과 보기까지 걸린 시간, 앱 밖 이탈과 앱 안 탐색을 구분해 측정한다.
- 요구사항·이미지·메모 본문은 분석 이벤트에 수집하지 않는다.

실제 유료 생성 없이 mock 상태로 UI를 먼저 평가할 수 있다.
