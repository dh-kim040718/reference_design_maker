# Phase 3 공유 수신·미리보기 보강

기준일: 2026-10-29. **PC 범위 구현·자동 검증 및 사용자 확장 설치·동작 확인 완료, 모바일 OS 공유 메뉴 실기기 검증 대기**다. 사용자가 ZIP 다운로드·로컬 압축 해제·Chrome 확장 설치 및 기능 동작을 확인했다. Phase 2 저장 MVP의 완료 상태는 유지하며, 모바일을 포함한 Phase 3 전체 완료 판정은 실기기 확인 전까지 보류한다.

## 바로 사용하기

앱 `http://127.0.0.1:5174/`에 로그인한 뒤 상단 **외부에서 저장**을 연다. 직접 주소는 `/collect`다.

### 북마크바 저장 버튼

‘＋ 레퍼런스 저장’을 북마크바로 드래그한다. 필요하면 Ctrl+Shift+B로 북마크바를 표시한다. 외부 페이지에서 버튼을 누르면 현재 URL·제목과 선택한 텍스트가 채워진 새 수집 창이 열린다. 위치·메모를 확인한 뒤 저장한다. 자동 저장은 하지 않는다.

버튼을 누를 수 없는 환경에서는 ‘북마크 주소 복사’로 북마크 URL을 직접 설정하거나 확장 프로그램·URL 직접 입력을 사용한다. 새 창 차단이나 사이트 정책으로 북마크 실행이 제한될 수 있다.

### Chrome·Edge 확장 프로그램

1. `/collect`에서 확장 프로그램 ZIP을 다운로드하고 압축을 푼다.
2. `chrome://extensions` 또는 `edge://extensions`에서 개발자 모드를 켜고 압축해제된 확장 프로그램을 로드한다.
3. 폴더 안의 `manifest.json`이 있는 위치를 선택하고 툴바에 고정한다.
4. 확장 옵션의 앱 주소를 현재 앱 주소와 정확히 맞춘다. 기본값은 `http://127.0.0.1:5174`다. localhost·127.0.0.1·포트가 다르면 별도 로그인 출처로 취급된다.
5. 외부 페이지에서 확장 버튼을 누르고 앱의 확인 화면에서 저장한다.

확장은 `activeTab`, `storage` 권한만 사용한다. 클릭한 페이지의 URL·제목만 전달하며 앱의 로그인 토큰을 읽거나 모든 사이트를 상시 수집하지 않는다. 내부 브라우저 페이지·파일 URL은 직접 입력 대체 화면으로 연다. HTTPS 앱 주소 또는 loopback HTTP 주소만 연결 설정으로 허용한다.

소스는 `browser-extension/`, 사용자 다운로드 파일은 `frontend/public/reference-maker-extension.zip`이다. 스토어 게시·사용자 브라우저에 자동 설치는 하지 않았다.

### 설치형 앱 공유 대상

설치 manifest에 GET 방식 `/share`와 URL·제목·텍스트 매핑을 추가했다. 지원 브라우저가 설치 이벤트를 제공할 때만 앱 내 설치 버튼을 표시한다. 실제 공유 메뉴 등록은 기기·운영체제·브라우저 지원과 앱 설치에 따라 달라진다.

현재 PC의 loopback 주소는 휴대전화에서 접근할 수 없다. 모바일 검증에는 휴대전화가 접근 가능한 HTTPS 환경이 필요하며 이번 작업에서 외부 배포는 하지 않았다. 파일·이미지 바이너리를 OS 공유로 직접 받는 기능은 제공하지 않는다. 링크를 먼저 받은 뒤 기존 이미지 선택·붙여넣기로 보완한다.

## 공유 수신 계약

- `GET /share?url=...&title=...&text=...`를 공통 수신 경로로 사용한다. 설명 텍스트 별칭 `description`도 읽되 별도 설명 입력은 다시 만들지 않는다.
- URL만 있거나 제목·텍스트가 빠져도 진행한다. 본문에 포함된 HTTP(S) 링크도 추출한다. 여러 링크는 첫 번째를 제안하고 사용자가 확인하게 한다.
- 사용할 수 있는 URL이 없거나 지원하지 않는 주소면 원인을 안내하고 URL 직접 입력을 제공한다. 미지원 미디어 필드는 무시하며 링크 저장을 막지 않는다.
- URL은 4096자, 제목 200자, 메모 5000자 범위로 정리한다. 수신 텍스트는 최대 8000자를 읽는다. 북마크 버튼은 선택 텍스트를 최대 1000자 전달하고 URL 길이가 과도해지면 선택 텍스트·제목을 우선 제외한다.
- 공유 정보는 현재 탭 sessionStorage에 15분간 임시 보관한다. 받은 외부 URL·텍스트를 주소에서 제거하고 불투명한 수신 ID를 가진 `/references/new?shared=...`로 전환한다.
- 로그인이 필요하면 받은 내용을 유지하고 로그인·회원가입 뒤 돌아온다. 아직 DB에 저장된 것은 아니며 사용자가 저장해야 생성된다.
- 분류는 기존 계정의 유효한 마지막 저장 위치를 제안하며 변경할 수 있다. 보관된 위치는 사용하지 않는다.
- 저장 성공·취소·명시적 로그아웃·로그인/회원가입 이외의 경로로 이탈할 때 임시 공유 정보를 정리한다. 다른 계정으로 전환하면 이전 계정의 초안·화면 상태를 제거한다.

## 새 수집 창의 로그인

같은 브라우저·같은 출처의 새 수집 창이 로그인 상태를 공유하도록 인증 세션을 localStorage에 보관한다. Phase 2의 탭 한정 sessionStorage 세션은 읽을 때 이전한다. 계정별 작성 초안은 계속 메모리에만 둔다.

다른 창의 로그인·로그아웃·계정 변경은 storage 이벤트로 동기화한다. 계정 전환 후 늦게 도착한 이전 계정 응답은 표시하지 않는다. 지원 브라우저에서는 Web Locks로 여러 창의 토큰 갱신을 직렬화한다. 로그아웃하면 현재 Supabase 세션을 폐기하고 같은 출처의 창들에서도 로그인 상태를 제거한다. 다른 기기·다른 출처의 별도 Supabase 세션을 일괄 폐기하는 기능은 아니다.

## 미리보기 보강

- 계정·원본 URL별 프로세스 메모리 캐시: 성공 5분, 실패 30초, 최대 128건. 프로세스 재시작 시 초기화된다.
- `POST /api/v1/references/preview`에 선택 입력 `refresh: true`를 추가했다. 상세의 ‘링크에서 불러오기’는 캐시를 건너뛰고 재시도한다.
- 실패 이유를 접근 제한·인증서·타임아웃·네트워크·페이지 접근 실패·응답 과대·대표 이미지 없음으로 구분한다. 실패해도 URL·메모 저장은 가능하다.
- DNS 검사·IP 고정 연결·TLS 검증·robots·리다이렉트 검사와 응답 크기 제한을 유지했다. HTTP 헤더 응답이 지연되어도 종료되도록 요청 기한에 연결을 중단하는 처리를 보강했다.
- 확인한 Pinterest 링크의 자동 수집 제한은 여전히 남는다. 봇 사칭·접근 제한 우회·이미지 URL 추정으로 해결하지 않는다.

## 설치·오프라인 범위

manifest와 192·512px 아이콘, 서비스 워커를 추가했다. 서비스 워커는 익명 오프라인 안내 HTML만 캐시한다. 계정 API·인증 토큰·사용자 레퍼런스는 캐시하지 않는다. 오프라인에서는 저장했다고 표시하지 않고 연결 확인·재시도를 안내한다. 백그라운드 저장·오프라인 편집 동기화는 미구현이다.

### 재검증

```powershell
backend\.venv\Scripts\python.exe scripts/package_collector.py --check
npm.cmd test --prefix browser-extension
Set-Location frontend
node browser-smoke.mjs chrome --thumbnail --share
node browser-smoke.mjs edge --thumbnail --share
```

확장 소스를 변경하면 저장소 루트에서 `backend\.venv\Scripts\python.exe scripts/package_collector.py`로 ZIP·아이콘을 다시 생성한다. 일반 검사·서버 실행·PostgreSQL 검증은 [README](../README.md)를 따른다. DB 변경은 없어 Alembic head는 `0003_thumbnails`를 유지한다.

## 남은 완료 게이트

1. 접근 가능한 HTTPS 환경에서 대상 모바일 기기 설치 → OS 공유 메뉴 → 저장 확인까지 검증하기.
2. 지원·미지원 출처와 기기 목록을 실측 결과로 확정하기. Edge의 실제 확장 설치도 추가 확인하면 해당 지원 기록에 반영한다.

PC 확장 다운로드·설치·기능 확인은 사용자가 완료했으므로 더 이상 미완료 항목으로 취급하지 않는다. 현재는 PC 기능을 사용하며 다음 개발을 진행할 수 있는 상태다. 모바일 공유 검증과 별도로 Pinterest의 자동 썸네일 수집 제한은 남아 있으며 이미지 선택·붙여넣기로 사용할 수 있다.

Phase 4의 AI 호출은 시작하지 않았다.
