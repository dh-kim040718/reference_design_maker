# Phase 4·5 실제 연동 평가 — 2026-11-02

## 승인과 범위

사용자는 기존 총 USD 1 예산 유지와 로컬 검증 프로세스에 한한 추가 3회(재생성 1회·편집 2회)를 승인했다. 기본 앱의 일 3회 제한과 `.env` 활성화 설정은 변경하지 않았다. 검증 프로세스에서만 누적 예약 상한 6으로 설정하고 종료 시 복원했다. 과거 기록 삭제·횟수 환급·자동 재시도는 없었다. 이번 승인된 추가 호출은 모두 사용했으며 추가 호출 권한으로 재사용하지 않는다.

자체 제작 입력과 기존 성공 결과를 재사용했다. 자료는 Git 제외 경로 `.phase4-checks/phase5-approved/`, 최초 성공 자료는 `.phase4-checks/approved-new-key-03/`에 보존했다. 키·로그인 정보는 보고서에 저장하지 않았다. 비교 화면은 `.phase4-checks/phase5-approved/comparison.html`, 종합 수치는 같은 폴더 `evaluation.json`이다.

## 실제 편집 어댑터

고정 모델 `gpt-image-2.5-flare-2026-09-08`, `POST /v1/images/edits`, 한 장·1024×1024·low·PNG를 유지했다. JSON `images[].image_url`로 원본, `mask.image_url`로 같은 크기의 PNG data URL을 전달한다. 공통 제공자 경로의 제한 시간·안전한 오류 분류·AI 표시·자동 재시도 금지를 재사용한다. `get_edit_provider`는 편집 활성화와 키가 모두 있을 때만 실제 어댑터를 반환하며 일반 앱에서는 비활성화를 유지한다.

2026-11-02 확인 자료: [편집 API](https://developers.openai.com/api/reference/resources/images/methods/edit), [모델](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare), [Standard 가격](https://developers.openai.com/api/docs/pricing). 100만 토큰당 텍스트 입력 USD 5·이미지 입력 USD 8·이미지 출력 USD 30을 적용해 추정했다. 전송 계약은 실제 호출 전에 mock으로 검증했다.

## 품질 검토와 출시 판정

전체 재생성은 사이드바·요약 카드 3개·큰 선 차트·주황색 방향을 유지했다. 이전 결과를 덮어쓰지 않고 새 작업·이력·사용량을 기록했다. 기본 탐색 시안으로 판단했지만 사용자 유용성 수용 여부는 별도 확인 대상이다.

마스크는 기준 생성 이미지 첫 카드 내부 `x=236..463, y=204..406`을 투명하게 지정했다. 원본/마스크/결과는 모두 1024×1024다.

| 편집 | 직접 관찰한 문제 | 보호 영역 변경 비율 | 판정 |
| --- | --- | --- | --- |
| 지시 있음 | 배경색 변경 외에 첫 카드의 24/Active items가 18/Finished로 바뀌고 옆 카드까지 침범 | 약 4.93% | 숫자·문구 유지와 선택 밖 보존 실패 |
| 지시 없음 | 첫 카드를 삽화로 바꾸고 선택 밖 차트에 월 표기를 추가 | 약 3.66% | 주변 보존 기준 실패 |

변경 비율은 원본 대비 RGB 최대 채널 차이 10 초과인 보호 픽셀의 비율이다. 앱의 AI 표시 하단 26줄은 제외했다. 픽셀 차이는 품질 점수가 아니며 렌더링 변화도 포함할 수 있어 카드 내용·차트의 의미 있는 변경을 직접 검토한 결과와 함께 판정했다. 원본 파일을 합성하거나 수정하지 않았다.

**영역 편집은 출시 제외·비활성화 유지.** 입력 수락·성공 응답과 품질 합격을 구분한다. 프롬프트/마스크 보강이나 보호 영역 합성 방식을 후속 검토하되 추가 유료 실험은 이번 승인에 포함하지 않는다. 지시 없는 변형은 기능적인 카드 정보를 얼마나 유지해야 하는지도 추가 정의해야 한다.

## 실제 결과 재사용 검증

- 추가 작업 모두 같은 요청 ID 재제출 시 기존 작업을 반환했고 추가 제공자 호출은 없었다. 이력에서 생성/편집을 구분했고 인증 없는 상세 조회는 401이었다.
- 각 추가 작업 실행 시 기존 기준 생성 결과의 DB 조회가 계속 가능함을 확인했다. 이후 삭제 검증 전까지 이전 결과를 보존했다.
- Chrome에서 기준 결과 재방문·새로고침·PNG 다운로드를 검증했다. 다운로드 SHA-256은 저장된 PNG와 일치했다.
- Edge에서 기준 결과의 재방문·다운로드·삭제·삭제 후 접근 차단을 검증했다. Chrome에서도 실제 지시 편집 결과에 같은 검증을 수행했다. 390px 가로 넘침 없음과 로그아웃도 확인했다.
- 브라우저 검증은 유료 예약 POST를 차단하도록 구성해 유료 호출 0회다. 삭제된 DB 결과의 비교용 PNG·보고서는 보존했고, 전체 재생성·무지시 변형 결과는 앱에 남겨 재사용할 수 있다.
- 계정 격리·공통 한도·오류/불명·중복·삭제 경합은 자동 테스트로 검증한다. 고의로 잘못된 키를 사용하거나 실제 실패를 만들기 위한 유료 재호출은 하지 않았다.
- 백엔드 전체 136개(SQLite/PostgreSQL)와 lint 통과. 프런트엔드 직전 47개 테스트/빌드 결과를 유지하고 이번에는 실제 Chrome·Edge 결과 흐름을 추가 검증했다. Starlette/httpx 경고 1개는 남아 있다.

## 남은 확인

실제 Usage/Billing의 비용·잔여 예산, 생성/재생성 결과에 대한 사용자 유용성 수용과 장당 비용/시간 기준은 미확정이다. 과거 구형 키 거절 원인은 당시 정보가 없어 복원 불가지만 현재 키의 생성/편집 연동 차단은 해소됐다.

Phase 4 실제 연결 및 Phase 5 재생성/편집 실험은 수행했다. 실제 청구·사용자 수용 확인 전 Phase 4 전체 완료로 표시하지 않는다. Phase 5는 품질 미달에 따라 편집을 출시에서 제외하는 결론을 기록했으며 편집 품질 합격으로 표시하지 않는다. Phase 6 운영·배포 작업으로 넘어가지 않았다.
