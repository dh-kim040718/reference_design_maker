# 프로젝트 전체 레퍼런스 종합 시안

2026-11-02 사용자 의도 확인: AI 시안은 선택한 레퍼런스 하나의 변형이 아니라 프로젝트 전체 레퍼런스 이미지와 각각의 메모를 검토한 결과다. 이 결정은 과거 단일 레퍼런스 생성 설계보다 우선한다. 기존 결과를 프로젝트 종합 결과로 재분류하지 않는다.

## 사용자 흐름

현재 선택 UX: 기본은 전체 선택이며 카드별 체크박스와 상단 전체 선택(부분 선택 상태 포함)·전체 해제로 생성 대상을 지정한다. 체크한 이미지와 해당 메모만 준비·전송하고, 0개 선택은 차단한다. 서버는 선택 ID의 소속·중복과 이미지 ID의 정확한 일치를 검증하며 선택 목록을 결과 스냅샷에 보존한다. 명시적인 선택 목록이 없는 기존 요청은 전체 입력 일치 검증을 유지한다.

1. 프로젝트/산출물 목록의 **AI 시안** 탭 또는 **프로젝트 AI 시안 만들기**로 들어간다. 레퍼런스 상세의 생성 블록은 제거했다. 상세의 프로젝트 이름을 누르면 프로젝트로 돌아간다.
2. 프로젝트 요구사항을 입력한다. 별도 저장 없이 생성 CTA가 현재 입력값을 사용하고 결과 스냅샷에 기록한다. 충돌 시 추가 요청 → 프로젝트 요구사항 → 레퍼런스 메모 순으로 우선한다. 기본은 프로젝트 전체이며, 분류 화면의 **이 분류로 AI 시안 만들기**는 해당 분류의 모든 이미지·메모만 사용한다.
3. 카드는 썸네일·제목·메모 중심으로 표시하며, 분류명은 전체 보기에서만 표시한다. 생성 CTA에서 저장된 data URL 또는 인증된 `/references/{id}/generation-source`의 이미지 데이터를 자동 준비한다. 외부 주소는 사용자가 저장한 이미지 주소만 사용하며 공개 IP 검증·리다이렉트 검증·10초·8MB·이미지 규격 제한을 적용한다. 원본은 메모리에서만 사용하고 응답은 `no-store`다. 한 장이라도 실패하면 유료 생성 요청을 보내지 않고 해당 카드에만 이미지 교체를 표시한다. 정상 카드에는 준비 상태나 이미지 선택 버튼을 표시하지 않는다.
4. 이번 프로젝트 시안의 추가 요청을 선택적으로 작성한다. 모든 입력 이미지 사용 권한을 확인한 후 **프로젝트 시안 1장 만들기**를 누른다. 요구사항 미저장·이미지 누락·한도 초과·보관 상태·예산/키/사용 승인 미충족이면 차단한다.
5. 프로젝트 시안 이력에서 결과를 다시 확인·다운로드·삭제한다. 결과에는 당시 프로젝트 이름·요구사항·전체 레퍼런스 제목/분류/메모 스냅샷을 표시한다. 이후 원본 메모를 수정해도 과거 입력을 바꾸지 않는다.
6. 재생성은 프로젝트 준비 화면으로 이동해 이전 추가 요청을 복원한다. 현재 요구사항과 전체 레퍼런스를 다시 확인하고 이미지를 재선택한다. 기존 결과는 보존하고 새 요청/사용량으로 처리한다.

원본 이미지는 서버 메모리에서 요청에만 사용한다. 준비 화면을 나가거나 새로고침하면 이미지를 다시 선택해야 한다. 연결 결과가 불명확하면 입력을 잠그고 같은 요청 ID로 상태만 확인한다. 새로고침 후에는 이력을 먼저 확인한다.

## 서버 계약

| API | 역할 |
| --- | --- |
| `PATCH /api/v1/projects/{id}/brief` | 프로젝트 요구사항, 최대 5,000자 저장 |
| `GET /api/v1/projects/{id}/generation-context` | 전체 입력 메타데이터·재사용 가능한 사용자 미리보기·내용 digest·입력 제한/보관 상태 |
| `POST /api/v1/projects/{id}/generations` | `request_id`, `context_digest`, 전체 `sources[{reference_id,image}]`, 선택 `instruction`, `rights_confirmed`로 예약 |
| `GET /api/v1/projects/{id}/generations` | 최근 100개 프로젝트/과거 단일 참고 작업을 scope로 구분해 조회 |
| 기존 `/api/v1/generations/{id}` GET/DELETE | 상태·비공개 결과·프로젝트 입력 스냅샷·삭제 재사용 |

입력과 상태는 인증·소유권을 확인한다. 프로젝트 행 잠금 아래 현재 목록/메모 digest를 재확인하고 누락·중복·타 프로젝트 이미지 ID·변경된 내용은 유료 예약 전에 거절한다. 같은 입력의 재제출은 프로젝트가 나중에 수정돼도 기존 작업을 반환한다. 동일 ID로 입력이 바뀌면 409다. 이미지 순서는 서버의 레퍼런스 순서로 고정하고 각 이미지 번호와 해당 메모를 연결한다. 메모가 없는 자료는 이미지 중심으로 참고한다.

프로젝트 요구사항을 메모 충돌의 우선 기준으로 사용하고 단순 콜라주가 아닌 일관된 한 장을 요청한다. 프롬프트에는 프로젝트 이름/요구사항, 번호별 이미지 제목/분류/메모, 추가 요청을 구분한다. 기존 일 3회·사용자 진행 1개·전역 금액 예약·자동 재시도 금지·비밀 제거 오류·오래된 작업 정리·AI 표시·비공개 조회를 공유한다.

## 전체 입력 보장과 제한

현재 공식 [이미지 편집 JSON API](https://developers.openai.com/api/reference/resources/images/methods/edit)를 2026-11-02 확인했다. `images`는 최대 16개, `prompt`는 최대 32,000자다. 구현은 개별 PNG/JPEG/WebP 8MiB·1,600만 화소, 전체 이미지 합계 16MiB로 더 제한한다. 프록시의 24MiB 요청 한도 안에서 base64 본문을 전달하기 위한 제한이다.

- 16개를 넘으면 전체 개수를 명시하고 생성 준비를 차단한다. 첫 일부 자료를 가져와 전체 검토처럼 표시하지 않는다.
- 이미지가 하나라도 빠지거나 누락·중복 ID가 있으면 생성하지 않는다. 메모도 길이 초과 시 잘라내지 않고 안내한다.
- 서버가 이미지 디코딩·차원·합계 크기와 전체 프롬프트 길이를 검사한다. 요구사항/참고 메모가 바뀌면 **프로젝트 입력 새로고침** 후 다시 검토한다.
- 분할 검토·요약·자동 대표 이미지 선택은 구현하지 않았다. 큰 프로젝트는 현재 범위를 먼저 정리해야 하며 추후 설계 대상이다.
- 이미지 수가 늘면 입력 비용이 증가할 수 있다. 기존 한 장 테스트 비용을 프로젝트 전체 생성 비용으로 간주하지 않는다. 새 흐름의 실제 비용/종합 품질은 별도 승인·평가 전까지 미검증이다.

## 저장·마이그레이션·과거 결과

Alembic head는 `0009_project_concepts`다. `projects.brief`, Generation의 nullable reference ID·project ID·scope·프로젝트 입력 JSON 스냅샷을 추가했다. 기존 작업은 프로젝트 ID를 연결하되 `scope=reference`로 유지하고 **과거 단일 참고 시안**으로 표시한다. 새 작업은 `scope=project`, `reference_id=null`이다. 스냅샷에는 메모·원본 링크·분류·이미지 해시를 저장하며 이미지 본문은 저장하지 않는다.

기존 `/references/{id}/generate` UI 주소는 해당 프로젝트의 새 준비 화면으로 이동한다. 과거 결과 화면의 새 시안 진입도 프로젝트 전체 흐름으로 연결한다. 기존 단일 참고 API/검증 도구는 과거 기록 호환을 위해 유지하지만 새 UX 진입점에서는 사용하지 않는다.

마이그레이션 전에 현재 DB를 `.phase6-backups/20261102_031121_ec048100/`에 백업했다. 프로젝트 요구사항이나 프로젝트 시안이 존재하면 데이터 손실을 막기 위해 downgrade를 거절한다. 백업은 0007/0008의 알려진 구조를 읽기/호환 변환하며 과거 비용 미확정은 유지한다. 0009 로컬 PostgreSQL 복원 훈련도 통과했다: `.phase6-backups/20261102_032649_1045db0a/report.json`.

## 검증과 남은 실검증

후속 마무리에서 프로젝트 스냅샷·비공개 결과·금액 예약의 SQLite/실제 PostgreSQL 복원과 최신 컨테이너의 API/웹 번들 포함 검증을 추가했다. 최신 전체 검증은 백엔드 175개 통과·6개 제외다. [로컬 마무리 상태](./local-release-status.md)를 따른다. 아래 173개는 UX 구현 직후 기록이다.

- 백엔드 전체 173개 통과·6개 제외. SQLite/로컬 PostgreSQL에서 분류를 가리지 않는 전체 입력, 메모 연결, 스냅샷 보존, 변경/누락/소유권/보관/권한/예산/길이/크기 차단, 중복·삭제 재제출과 다중 이미지 제공자 mock 계약을 검증했다. 제외된 PostgreSQL 백업 케이스는 기존 별도 CLI 훈련 범위를 따른다.
- 프런트엔드 56개·타입 검사 포함 빌드·lint 통과. 전체 입력 준비·누락 차단·요구사항 저장·불명 시 같은 요청 유지·과거 이력 구분·프로젝트 결과 스냅샷/재생성 경로를 검사했다. 백엔드 lint도 통과했다.
- Chrome·Edge에서 로그인→레퍼런스 저장/메모 수정→상세 생성 블록 없음→프로젝트 AI 탭→서로 다른 두 분류의 이미지/메모 전체 표시→요구사항 저장→미리보기 일괄 선택→유료 버튼 차단→390px 가로 넘침 없음→로그아웃을 확인했다. `.phase2-checks/*-project-generation-*.png`에 화면을 보존했다.
- 초기 DB 연결 시간 초과는 Docker 엔진이 꺼진 상태였으며 엔진을 시작한 뒤 전체 PostgreSQL 검증을 다시 통과했다. 브라우저 스크립트의 새 한글 문자열 인코딩 문제도 수정 후 재검증했다.
- 이번 작업의 실제 유료 AI 호출은 0회다. 단일 참고 테스트의 품질·비용 기록을 새 종합 생성 게이트로 재사용하지 않는다. 실제 프로젝트 다중 입력의 유용성·메모 반영·충돌 처리·비용 평가, 큰 프로젝트 분할 검토 설계는 후속 항목이다. 기본 생성/편집 활성화와 예산 설정은 바꾸지 않았다.
