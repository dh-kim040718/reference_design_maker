# 레퍼런스 메이커 발전 방향 조사

조사일: 2026-11-03. 공식 제품 안내·도움말·디자인 사례와 현재 코드 기준.
이번 작업은 조사와 제안이며, 아래 기능을 구현하거나 유료 API를 호출하지 않았다.
외부 제품을 로그인하여 직접 조작한 사용성 테스트는 아니므로 실제 화면의 모든 동작을 검증한 것은 아니다.

## 제품 방향

‘이미지 북마크 + 생성 버튼’에서 ‘참고할 요소를 정하고, 시안을 비교하여 디자인 방향을 선택하는 공간’으로 발전시킨다.
현재의 흑백 테마, 간결한 카드, 프로젝트·분류 범위, 생성 전 검토 흐름을 유지한다.
자료와 결과 이미지가 시각적인 중심이 되게 하며, 대시보드용 통계·메뉴를 목적 없이 추가하지 않는다.

## 현재 구현과의 차이

- 프로젝트·분류별 조회, 생성용 레퍼런스 선택, 전체 선택·해제, 메모, 결과 다운로드·재생성 진입은 이미 있다.
- 선택에 더해 ‘이 이미지의 무엇을 참고할지’를 구조화하는 필드는 없다.
- 생성 이력은 텍스트 링크 중심이며 두 결과를 같은 화면에서 비교하거나 채택하는 기능은 없다.
- 라이브러리의 분류·진행/보관 필터는 있으나 제목·메모 검색 UI는 없다.
- 결과 상태 조회는 정상 응답에서만 다음 타이머를 예약한다. 일시적 GET 실패 후 폴링이 멈출 수 있다.
- 예산은 실제 청구액이 아니라 서버의 예약 금액으로 차단한다. 한도 조정 UI와 실제 청구 확인은 별개다.

## P0 — 생성 경험의 신뢰성

### 상태 조회 복구와 작업 복귀

GET 상태 조회 실패를 생성 실패와 구분하고 ‘연결 복구 중’을 표시한다.
제한된 재시도·간격 증가와 수동 상태 확인을 제공한다. 유료 POST를 자동 반복하지 않는다.
앱 안을 탐색할 때 ‘시안 생성 중 · 결과 보기’ 작은 진입점을 제공한다.
정상 진행·연결 지연·결과 불명·실패·완료를 mock으로 검증한다.
원본 비보관 정책상 서버 재시작 후 자동 재개는 약속하지 않는다.

### 예산 설명

‘AI 예산 한도 도달’만 표시하는 대신 ‘앱 설정 한도 / 예약 금액 / 추가 요청 가능 여부’를 구분한다.
일일 횟수 제한과 누적 예약 예산을 구분하고 실제 청구액은 확인되지 않으면 미확인으로 표시한다.
예산을 자동 증액하거나 실제 청구 정산 없이 예약을 풀지 않는다.

## P1 — 핵심 제품 가치

### 1. 레퍼런스별 참고 역할

선택한 이미지에 ‘전체 분위기 / 레이아웃 / 색감 / 컴포넌트’ 역할을 선택적으로 부여한다.
예: 첫 번째 이미지=색감, 두 번째=그래프 표현, 세 번째=전체 배치.
기본은 ‘전체 참고’로 두어 기존 메모만으로도 생성 가능하게 한다.
역할 편집은 이미지 선택 후에만 드러내고 카드마다 항상 버튼을 추가하지 않는다.
이 역할은 모델의 정확한 가중치가 아니라 생성 지시다. 반영 비율이나 완벽한 보존을 보장하지 않는다.
역할을 요청·프롬프트·스냅샷·재생성에 모두 보존해야 한다.

### 2. 이미지 영역 메모

이미지 확대 보기에서 사각 영역을 지정하고 ‘이 헤더 높이와 여백 참고’ 등 메모를 붙인다.
일반 메모는 계속 사용 가능하며 좌표는 정규화해 반응형 화면에서도 연결한다.
긴 모바일 이미지의 부분을 참고할 때 특히 유용하다.
초기에는 미리보기 기준 좌표와 메모만 저장하고, 생성 시 현재 이미지에 적용한다.
원본 교체·버전 변경 시 영역 재확인 안내가 필요하다. 영구 원본 저장 정책을 바꾸지 않는다.

### 3. 시안 갤러리·비교·채택

기존 ‘시안 이력’을 이미지 갤러리로 발전시킨다. 이미지·이름·분류·생성일을 먼저 보여준다.
두 시안을 선택하면 같은 크기의 뷰포트로 나란히 비교하고 각 입력 차이를 접어서 제공한다.
‘채택한 시안’을 표시하고 다음 접속 때 이어볼 수 있게 한다. 채택은 파일 확정·완성 디자인 보증이 아니다.
단순 비교·이름 변경·채택은 유료 생성이 필요 없다.
새 변형 생성은 추가 요청이며, 기존 결과의 픽셀을 유지하는 편집과 구별한다.

### 4. 검색과 선택 시 일괄 작업

기존 분류 줄에 짧은 검색창을 배치한다. 현재 프로젝트·분류 안의 제목·메모·URL 검색부터 시작한다.
현재 범위를 명시하고 범위 전환은 사용자가 요청할 때만 제공한다.
검색은 현재 페이지뿐 아니라 서버의 전체 해당 범위에서 수행하고 페이지 이동 시 조건을 유지한다.
선택 모드에서만 ‘분류 이동 / 보관 / 시안 만들기’를 표시한다. 전체 선택이 현재 페이지인지 전체 검색 결과인지 명시한다.
생성 이미지 수 제한을 초과하면 조용히 일부만 사용하지 않고 사용자가 줄이도록 안내한다.
키워드 검색부터 구현하면 임베딩·OCR·추가 AI 비용 없이 시작할 수 있다.

## P2 — 시각적 완성도와 확장

### 5. 검토용 무드보드·발표 보기

기본 그리드를 유지하면서 보기 옵션으로 이미지 중심 무드보드를 제공한다.
메모·URL·날짜를 숨기고 필요한 이미지에만 설명을 표시한다. 전체 화면·확대·방향키·Esc를 지원한다.
채택 시안과 참고 이미지들을 묶어 한 장의 검토 자료로 내보내는 기능도 후속 후보다.
무한 캔버스·자유 배치 편집기부터 만들기보다 읽기 전용 발표 보기를 먼저 검증한다.
장식보다 이미지 확대·절제된 진입 전환으로 완성도를 높이며 reduced-motion을 지원한다.

### 6. 프로젝트 다시 시작하기

프로젝트를 열면 기존 레퍼런스가 중심이고, 최근 시안이 있을 때만 작은 ‘최근 시안 이어보기’를 제공한다.
대표 이미지·짧은 프로젝트 목적·최근 결과로 프로젝트를 구분한다.
별도 통계 홈이나 커다란 히어로를 추가하지 않는다. 프로젝트가 많아질 때 접을 수 있는 탐색 패널을 검토한다.

### 7. 결과 후속 활용

결과 이미지·프로젝트 요구사항·선택한 참고 이미지 목록·메모를 묶는 내보내기를 검토한다.
디자이너가 Figma 등에서 다시 제작할 때 맥락을 함께 전달하는 것이 목적이다.
현재 결과는 래스터 이미지이므로 다운로드만으로 편집 가능한 Figma 레이어나 구현 코드를 제공한다고 표현하지 않는다.
공개 링크·팀 코멘트·권한 관리는 실제 공유 요구를 확인한 뒤 별도로 설계한다.

## 추천 구현 순서와 검증

1. P0 상태 조회 복구·예산 설명: 네트워크 오류 후 자동 회복, 중복 유료 요청 0건 확인.
2. 참고 역할 + 최소 영역 메모: 사용자가 긴 문장을 쓰지 않고 ‘무엇을 참고할지’ 지정할 수 있는지 관찰.
3. 시안 갤러리·2개 비교·채택: 결과를 선택하고 이유를 기록하는 데 드는 이동·시간 측정.
4. 제목·메모 검색 + 일괄 분류: 수십~수백 개 테스트 자료에서 검색 범위·결과 개수·페이지 동작 검증.
5. 발표 보기: 툴바 없이 이미지·메모만으로 디자인 방향을 설명할 수 있는지 검증.

화면·이력·검색·상태 복구는 유료 호출 없이 테스트 가능하다.
참고 역할·영역 메모의 생성 품질 개선은 기존 입력과 동일 조건의 유료 비교 검증이 따로 필요하다.
분석 시 요구사항·메모·이미지 본문은 수집하지 않고 결과 확인·비교·채택 등 동작만 최소한으로 측정한다.

지금 보류할 항목: 대형 분석 대시보드, 무한 캔버스 편집기, 다중 모델 선택, 자동 다량 생성,
공개 커뮤니티, 자동 분류·시각 검색의 일괄 도입. 먼저 소규모 핵심 흐름을 검증한다.
