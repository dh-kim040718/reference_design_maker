# 로컬 마무리 상태 — 2026-11-02

사용자가 정한 **로컬 준비 범위**에서 마무리 검증을 보강했다. 원본 비보관·자동 재개 제외 정책을 유지한다. 실제 API 호출·청구 원장 수정·원격 배포·원격 백업·알림 설치는 하지 않았다.

## 이번 검증

- 프로젝트 시안의 nullable reference ID, 전체 입력 스냅샷, 생성 이후 바뀐 현재 요구사항, 비공개 결과 이미지, 금액 예약을 함께 백업·복원하는 테스트를 추가했다. SQLite와 새로 만든 실제 PostgreSQL DB 모두에서 확인했다. 테스트가 만든 PostgreSQL DB만 종료 후 삭제했다.
- 실제 로컬 앱 데이터의 격리 복원도 통과했다: `.phase6-backups/20261102_051000_df1ceeed/report.json`. 원본 DB는 덮어쓰지 않았고 해당 훈련용 복원 DB는 자동 삭제하지 않았다.
- 최신 API/Web 이미지를 빌드하고 OpenAI 키 없는 임시 컨테이너에서 프로젝트 API의 OpenAPI 등록, 프로젝트 생성 웹 번들 포함, SPA·API 프록시·복원 DB readiness를 확인했다.
- 컨테이너 결과: `.phase6-backups/container_smoke_371869db2d/report.json`. 임시 컨테이너·네트워크와 DB 연결용 임시 env 파일이 제거된 것을 확인했다. 첫 실행 실패 원인은 확정하지 않았고 단계별 진단을 추가한 재실행은 통과했다. 운영 안정성 전체를 보장하는 검증은 아니다.
- 백엔드 **175개 통과·6개 제외**, lint 통과. 제외 항목은 기존 공통 fixture의 PostgreSQL 백업 시나리오다. 새 프로젝트 복원 테스트는 PostgreSQL에서도 실제 실행했다. Starlette/httpx 경고 1개는 남아 있다.
- 프런트엔드 직전 56개·빌드/lint·Chrome/Edge 검증 결과를 유지한다. 이번에는 프런트엔드 제품 코드를 변경하지 않았다. 공개 산출물 비밀 검사도 통과했다.
- 개발 화면 `/projects`와 `/health/ready`는 HTTP 200이다. 확인 주소: `http://127.0.0.1:5174/projects`.

## 다음 단계의 조건

1. **실제 종합 생성:** 정확한 호출 수/예산 승인, 기존 사용 내역/예약 대조와 금액 통제 절차가 필요하다. 과거 단일 참고 성공/비용을 프로젝트 종합 증거로 간주하지 않는다. [PROJECT-01~05](./deferred-api-work.md)에서 추적한다.
2. **사용자 확인:** 전체 요구사항·레퍼런스/메모 목록과 실제 결과의 유용성 확인이 필요하다. 현재 입력 한도 초과는 명시적으로 차단한다.
3. **운영 대상:** 호스팅/서버·백업 저장소·암호화/보존 정책·알림 수신 방식이 정해져야 실제 연결을 수행한다. 현재 미정이므로 외부 전송/설치/배포를 하지 않는다.
4. **출시 판정:** 원격 CI·HTTPS·실기기 회귀·Auth/Storage 전체 복구·실제 청구·사용자 수용까지 확인한 뒤 판단한다. 로컬 통과만으로 출시 완료로 표시하지 않는다.
