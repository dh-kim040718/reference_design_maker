# 생성 흐름 안정성 보완 — 2026-11-05

새 기능 확대보다 기존 생성 흐름의 차단·복구 문제를 우선 수정했다.

## 반영

- 결과 상태 GET 조회의 연결 오류·5xx·429는 2/4/8/16초 간격으로 최대 4회 재조회한다. 정상 응답 후 기존 조회 주기로 돌아가고 완료 상태에서는 멈춘다.
- 자동 복구가 끝나거나 인증/권한 등 재시도 대상이 아닌 오류이면 수동 상태 확인을 제공한다. 화면을 떠나면 조회 예약을 취소한다.
- 상태 재조회는 유료 생성 POST를 다시 실행하지 않는다. 서버 재시작 후 작업 자동 재개를 추가한 것이 아니다.
- 생성 준비에 전체 레퍼런스를 표시한다. 16개 초과라는 이유로 선택 목록을 비우지 않는다.
- 생성 입력은 선택한 1~16개로 제한한다. 임의로 앞의 16개만 사용하지 않는다. 초과 시 전체 해제·개별 선택으로 사용자가 범위를 정한다.
- 서버에서도 선택 개수·소유 범위·이미지 일치를 검증한다. 최종 프롬프트 길이와 이미지 합계 제한은 유지한다.
- 선택에서 제외한 메모가 준비 화면의 길이 계산을 불필요하게 막지 않도록 선택별 길이 정보를 제공한다. 최종 길이 판정은 서버에서 수행한다.

## 검증 범위

프런트엔드 mock 회귀와 백엔드 격리 테스트로 확인한다. 실제 유료 API 호출·청구 변경·운영 배포는 없다. PostgreSQL 통합 검사를 별도로 실행하지 않았다면 제외된 결과를 통과로 계산하지 않는다.

## 후속 우선순위

생성 전 차단 이유 안내 통합, 현재 구현에 맞는 PRD/SPEC/README 정합화가 다음 후보이다. 검색·시안 비교 등 신규 기능과 운영 배포는 이번 수정에 포함하지 않는다.

## 후속 반영 — 2026-11-05

- 생성 CTA와 제출 처리에 같은 차단 조건을 사용한다. 요구사항·규격·선택 수·참고 영역·크기/문자 한도·권한·보관·일일 횟수·서버 예산 조건을 안내한다.
- 화면에서 고칠 수 있는 조건은 해당 위치로 연결한다. 해결한 항목은 즉시 사라지며 서버 예산 제한을 권한 체크로 해제할 수 있는 것처럼 안내하지 않는다.
- `AGENTS.md`, 최신 범위/검증표 `docs/current-status.md`, README 실행 안내를 정리하고 PRD/SPEC/개발계획에서 현재 기준으로 연결했다.
- 프런트엔드 88개 테스트, 빌드·린트 통과. 공개 텍스트 산출물 20개 비밀 패턴 검사 통과. 실제 유료 호출은 없다.
- 직전 백엔드 검증은 164개 통과·75개 PostgreSQL 관련 제외였다. 이번 안내/문서 작업에서 백엔드를 추가 수정하지 않았다.
