# 확장 프로그램 자동 썸네일

확장 버전 0.3.0은 아이콘을 누른 현재 탭의 이미지를 작은 JPEG 썸네일로 자동 변환하여 저장 확인 화면에 전달한다.

- Pinterest 핀 상세에서는 현재 열린 핀의 상세 이미지 DOM을 우선 확인한다. 관련 핀 목록에서 임의 이미지를 고르지 않는다.
- 일반 페이지는 Open Graph·Twitter 이미지·image_src 메타데이터를 확인한다.
- Pinterest DOM 선택자가 달라졌으면 페이지 JSON에서 현재 핀 ID에 해당하는 이미지 필드만 찾는다.
- HTTPS 이미지 주소로 브라우저에서 최대 640px JPEG를 만든다. 외부 이미지 접근이 막히면 화면에 완전히 보이는 해당 이미지 영역만 캡처한다.
- 캡처 전후 활성 탭과 주소를 확인한다. 전체 화면이나 다른 탭의 이미지를 저장 확인 화면에 전달하지 않는다.
- JPEG는 160,000자 이하로 제한한다. 자동 생성한 JPEG와 HTTPS 주소만 전달하며 SVG·임의 data/blob·로그인 정보가 포함된 주소는 제외한다.
- 사용자가 클릭한 탭에서만 activeTab+scripting 권한으로 실행한다. 상시 페이지 읽기나 전체 사이트 권한은 추가하지 않는다.
- 썸네일과 주소는 URL fragment로 전달하고, 앱 진입 시 주소창에서 제거해 세션 내 수집 정보로 보관한다.
- 저장 확인 화면에 확장 버전과 썸네일 수신 여부를 표시한다. JPEG는 기존 업로드 썸네일 저장 경로를 사용한다.
- 로그인 후에도 수집 정보와 미리보기가 유지된다. 저장 전 프로젝트·분류와 이미지를 확인한다.
- 앱 서버의 메타데이터 조회 실패가 이미 가져온 이미지를 지우지 않는다.
- 추출 실패·실행 제한 페이지에서는 기존 링크 저장 흐름으로 진행한다.
- JPEG 변환·영역 캡처가 모두 불가능하면 HTTPS 주소로 전달한다. 이 경우 원본의 이미지 삭제·접근 제한에 따라 미리보기가 실패할 수 있다.
- 유료 AI API 호출이나 자동 레퍼런스 저장은 하지 않는다.

## 업데이트

`browser-extension` 또는 새 ZIP을 압축 해제한 폴더를 사용한다.
`chrome://extensions`에서 해당 확장 프로그램을 새로고침하고 필요한 권한 안내를 확인한다.
버전 0.3.0을 확인하고 원본 페이지에서 확장 아이콘을 다시 누른다. 이전에 열어둔 저장 폼에는 새 썸네일이 소급 적용되지 않는다.
다운로드한 기존 폴더로 설치했다면 그 폴더의 파일도 새 버전으로 교체해야 한다.

검증: 확장 추출/전달/실패 fallback 계약 테스트, 프런트엔드 수신·로그인·미리보기 저장 테스트.
공식 API: https://developer.chrome.com/docs/extensions/reference/api/scripting
