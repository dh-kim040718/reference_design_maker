## 사용 흐름

`http://127.0.0.1:5174/`에서 레퍼런스 상세 → **AI 시안 만들기**로 들어간다.

1. PNG·JPEG·WebP 전체 이미지를 선택한다. 8MB·1,600만 화소 이하, 애니메이션 제외. 원본을 자동 축소하지 않는다.
2. 직접 올린 미리보기가 있으면 명시적으로 재사용할 수 있다. 축소 이미지임을 알린다. 외부 URL 이미지를 임의 수집하거나 접근 제한을 우회하지 않는다.
3. 저장된 메모를 확인하고 추가 요청을 선택적으로 적는다. 메모 없이도 생성할 수 있다. AI 입력 사용 권한 확인이 필요하다.
4. 사용자가 버튼을 눌렀을 때 한 장만 요청한다. 상태를 조회하고 결과를 다운로드·삭제한다. 재방문은 생성 이력에서 가능하다.

현재 생성 버튼은 승인 대기로 비활성화되어 있다. 페이지 진입·파일 선택만으로 유료 호출하지 않는다.

[공식 이미지 편집 API](https://developers.openai.com/api/reference/resources/images/methods/edit)와 [모델 정보](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)를 기준으로 구현했다. [공식 Standard 가격](https://developers.openai.com/api/docs/pricing)은 100만 토큰당 텍스트 입력 $5, 이미지 입력 $8, 이미지 출력 $30이다. 장당 고정 요금은 아니다. 실제 토큰 사용량을 측정하지 않아 장당 비용은 미확정이다. 호출 횟수 제한은 금액 지출 상한을 보장하지 않는다.

별도 승인 시 우선 한 장만 생성하고 실제 청구 내역·시간·유용성을 확인한 뒤 추가 호출을 판단한다. 총 테스트 예산은 아직 미정이다. `IMAGE_GENERATION_ENABLED=false`를 유지하고 키는 서버의 `OPENAI_API_KEY`에만 제공한다. 현재 개발 요청을 유료 호출 승인으로 간주하지 않았다.

## 서버와 데이터

- 인증·소유권·보관 상태·이미지 실제 디코딩·권한 확인 후 요청을 예약한다.
- DB UTC 일자별 quota 행 잠금으로 예약을 직렬화한다. 실패·응답 불명·삭제한 요청도 횟수를 돌려주지 않는다.
- `(owner_id, request_id)` 고유 제약과 입력 해시를 사용한다. 같은 입력·식별자는 기존 작업을 반환하며 같은 식별자의 입력 변경은 409다.
- 원본은 DB·디스크에 보관하지 않고 백그라운드 작업 메모리에서 한 번 전달한다. 요청 해시·추가 요청·메모 스냅샷·상태는 보관한다.
- 결과는 MVP DB의 비공개 data URL로 저장한다. 목록에는 이미지 본문을 제외하고 소유자 상세 API만 반환한다. 결과 API는 `Cache-Control: no-store`이며 서비스 워커에 캐시하지 않는다.
- 결과 화면·다운로드 파일명과 반환 PNG 하단의 `AI-generated concept` 표시를 유지한다.
- 사용자 삭제 시 이미지 본문을 지우고 중복 과금 방지·횟수 집계 기록은 남긴다. 백업 삭제 정책은 Phase 6에서 정한다.
- 모델·처리 시간·제공자가 반환한 숫자 토큰 사용량을 기록한다. 원시 오류·키는 노출하지 않는다. 사용량 미제공을 0원으로 추정하지 않는다.
- 연결 오류·타임아웃은 과금이 불명확할 수 있어 `unknown`으로 표시하고 재시도하지 않는다. 5분 넘게 남은 대기·진행 작업도 조회 시 불명으로 전환한다.

## 검증과 남은 게이트

2026-11-02 사용자 지침: 앞으로 유료 AI 호출을 최소화한다. 개발·화면·오류·회귀 검증에는 mock을 기본으로 사용하고, 실제 호출은 mock으로 확인할 수 없는 최종 연동·품질·비용 확인에 한정한다. 승인된 결과와 측정 기록은 재사용하고 단순 UI·문서 변경 때문에 재생성하지 않는다. 최초 실제 검증은 별도 승인 후 한 장으로 시작하며, 추가 호출 전에는 필요한 검증 항목을 명확히 한다. 이번 지침은 유료 호출 승인이 아니므로 비활성화 상태를 유지한다.

- 백엔드 66개 통과: SQLite·로컬 Supabase PostgreSQL, 마이그레이션 왕복/메타데이터 일치, 생성 성공·권한·키 누락·비활성화·한도·보관·계정 격리·중복·삭제·실패/불명, 제공자 HTTP 계약 mock.
- 프런트엔드 36개 통과: 승인 전 차단, 연결 오류 후 동일 요청 식별자, 결과 AI 표시/다운로드/삭제 진입 포함. lint·production build 통과.
- 실제 Chrome·Edge headless에서 로그인 → 저장 → 상세 → 생성 화면 → 승인 전 버튼 비활성화 → 390px 가로 넘침 없음 → 로그아웃 확인. 스크립트: frontend에서 `node browser-smoke.mjs chrome --thumbnail --generation` / `edge`.
- 브라우저 검증은 승인 대기까지이며 유료 성공 화면은 실제 생성으로 검증하지 않았다. 결과 화면 테스트는 테스트 mock을 사용한다.
- 원격 CI·배포는 이번 검증 범위에 없다. Starlette/httpx 호환성 경고 1개가 있지만 테스트 실패는 없다.

실제 API 권한·모델 사용 가능 여부·품질·생성 시간·장당 청구액은 승인 후 확인한다. BackgroundTasks는 단일 서버 MVP용이며 재시작 복구 큐가 없다. 자동 재전송 대신 불명 상태로 남긴다. 운영 전 작업 큐·금액 기반 차단·분산 실행·저장 용량·백업 정책은 Phase 6에서 보강한다.

- 새 중복 실행 방지/예산 검증 테스트 6개를 포함하여 비통합 테스트 54개와 backend lint가 통과했다. 이전 PostgreSQL 18개 통과 기록은 위 기록을 유지하되 이번에는 재실행하지 못했다.

## 승인된 최초 실제 호출 시도 — 2026-11-02

- 사용자가 총 USD 1 테스트 예산 및 최초 유료 생성 1회를 승인했다. 생성 검증 도구를 `--execute --approved-budget-usd 1`로 한 번 실행했다.
- 호출 직전 영구 중복 방지 기록이 생성됐다. 결과는 `unknown`, 오류는 `OUTCOME_UNKNOWN`, 처리 시간은 230ms였다. 결과 이미지·토큰 사용량을 받지 못했으며 실제 청구액은 미확정이다. 실제 제공자 도달 여부도 단정하지 않는다.
