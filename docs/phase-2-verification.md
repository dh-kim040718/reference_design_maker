# Phase 2 완료·검증 기록

기준일: 2026-10-29. 상태: **저장 MVP 구현·로컬 검증 완료**. 최신 사용자 확인: 상세 UI 정렬 수정 후 사용자가 확인했다. 원격 CI·운영 배포는 완료 범위에 포함하지 않는다.

이 문서는 Phase 2 종료 시점의 기록이다. 이후 공유 수신·로그인 창 간 동기화·설치형 앱 구현과 최신 검증은 [Phase 3 문서](./phase-3.md)를 따른다.

## 완료 기준 점검

| Phase 2 기준 | 구현·검증 결과 | 판정 |

| 메모 없이 저장하고 나중에 수정하기 | 선택 메모 저장, 추가·수정·비우기, 다른 필드 유지 | 완료 |
| 잘못된 입력·저장 실패를 성공과 구분하기 | 필드 검증, 로딩·실패 상태, 입력 유지, 성공 응답 이후 알림 | 완료 |

| 계정별 소유권·동기화 | Supabase Auth, FastAPI 소유권 검사, 서버 저장, 계정별 마지막 경로 | 완료 |

Phase 2는 링크 저장 MVP다. 모든 외부 사이트의 자동 이미지 수집은 완료 조건이 아니며, 실패해도 원본 링크·메모를 사용할 수 있어야 한다.

## 최종 구현 범위

- 회원가입, 로그인, 세션 검증·갱신, 현재 세션 로그아웃. 이메일 확인이 필요한 환경의 안내도 제공한다.
- 프로젝트·산출물 유형 생성·조회·이름 변경·보관·복구·페이지 이동.
- 프로젝트·유형 카드의 레퍼런스 추가 버튼과 실제 동작하는 열기 링크.
- URL 저장, 선택 제목·디자인 메모, 목록·상세 재조회 및 메모 편집. 설명은 입력·상세에서 제거하고 기존 DB 값은 보존한다.
- 마지막 저장 경로 자동 제안, 프로젝트 변경 시 유형 초기화, 추가 폼 안에서 프로젝트·유형 생성.
- 썸네일 파일 선택·Ctrl+V 붙여넣기·저장·수정, 프로젝트·유형의 표지 표시.
- 작은 추가 패널의 입력·미리보기 2열 배치, 목록·선택 항목을 함께 보는 상세 화면.
- 상세의 이미지·제목·분류 정렬, 같은 높이의 버튼, 별도 안내문, 메모 영역 및 저장·수정일 정리.
- 로딩·빈 목록·입력 오류·조회 실패·저장 실패 안내, 중복 제출 방지 및 미저장 이탈 확인.
- 인증 만료 시 현재 탭 메모리에 초안 유지, 같은 계정 재로그인 시 복구. 로그아웃·확인 후 이탈·새로고침에서는 복구하지 않는다.
- 저장과 마지막 경로의 단일 트랜잭션, 사용자 간 조회·변경 차단, 보관과 저장의 동시 요청 처리.

## Phase 3에서 선행 구현한 부분과 제한

공개 메타데이터 조회, 이미지 선택·붙여넣기, 기존 항목의 썸네일 자동 재조회, 실패 안내를 먼저 구현했다. 공개 URL 검증, DNS 결과 검사·IP 고정 연결, TLS 검증, robots 확인, 리다이렉트·크기·시간 제한을 적용했다.

공개 CA 목록을 보강해 로컬 인증서 문제를 수정했다. 다만 확인한 Pinterest 링크는 접근 정책상 자동 수집이 제한되어 썸네일 자동 표시를 보장하지 않는다. 공개 oEmbed 경로도 정책 확인 후에만 요청한다. 사용자가 이미지를 직접 선택하거나 붙여넣으면 저장·표시는 가능하다. 이를 Phase 2 미완료나 전체 Phase 3 완료로 표시하지 않는다.

## 최신 검증 결과

| 검사 | 결과·시점 |
|---|---|
| 프런트엔드 타입·린트·빌드 | 마지막 UI 정렬 수정 후 통과 |
| React 화면·API 클라이언트 | 19개 통과 |
| 백엔드 lint | 문서 정리 시점에 재확인, 통과 |
| 백엔드 전체 | 문서 정리 시점에 53개 전체 통과 |
| 빠른 테스트 / PostgreSQL | 39개 / 14개, 위 53개에 포함 |
| Chrome·Edge | 계정 로그인 → 프로젝트·유형 생성 → URL 저장 → 이미지 선택 → 메모 수정 → 새로고침 후 이미지 확인 → 모바일 너비 → 로그아웃 검증 |
| 추가 Chrome 검사 | 이미지 붙여넣기·저장·재조회, 최종 상세 정렬 및 모바일 배치 검증 |
| 사용자 확인 | 회원가입·저장 흐름 확인 및 마지막 UI 정렬 수정 수용 |

백엔드에는 Alembic upgrade/check/downgrade/upgrade, 사용자 격리, URL·경로 검증, 썸네일·프로젝트 표지, 보관·복구, 롤백, PostgreSQL 보관·저장 경합, DNS·robots·TLS 검증 테스트가 포함된다.

브라우저 검사는 headless 환경이다. 실제 터치 기기·스크린리더의 사용성 검증은 별도다. 기존 Starlette/httpx 테스트 클라이언트 deprecation warning 한 건이 있으나 테스트 실패는 아니다. 원격 GitHub Actions는 전체 integration 마커 테스트 실행으로 설정했지만 이번 작업의 원격 실행 결과는 확인하지 않았다.

## 실행·검증 안내

- 앱: `http://127.0.0.1:5174/`
- API 문서: `http://127.0.0.1:8011/docs`
- 로컬 Supabase Auth / PostgreSQL: `127.0.0.1:54321` / `127.0.0.1:54322`
- 현재 스키마: `0003_thumbnails`
- 초기 설치·재실행·테스트 명령: [README](../README.md)

기존 5173·8000 프로세스는 강제로 종료하지 않았다. 개발 프록시 대상은 Git에서 제외된 `frontend/.env.local`의 `VITE_API_PROXY_TARGET=http://127.0.0.1:8011`로 고정했다. 실제 앱 사용은 회원가입으로 시작할 수 있다.

자동 브라우저 검증이 필요하면 backend에서 `.venv\Scripts\python.exe -m tests.prepare_browser_user`로 로컬 계정을 준비한 뒤 frontend에서 아래 명령을 실행한다. 계정 정보와 스크린샷은 Git에서 제외된 `.phase2-checks/`에만 둔다. 이 검사는 로컬 테스트 계정에 표본 데이터를 생성한다.

```powershell
node browser-smoke.mjs chrome --thumbnail
node browser-smoke.mjs edge --thumbnail
node browser-smoke.mjs chrome --thumbnail --paste-thumbnail
```
